# MINDSPACE: خطة التنفيذ ومعايير القبول

الرموز: ✅ مكتمل ومختبر · 🟡 جزئي · ⬜ لم يبدأ

**تعريف «مكتمل»** (من الملف الأصلي): أن تكون الوظيفة تفاعلية وتعمل، وتُحفظ بياناتها، وتبقى بعد إعادة تحميل الصفحة، وتتصل بنموذج البيانات الحقيقي، وتنعكس تعديلاتها في المناظير ذات الصلة، وتعالج حالات الخطأ الأساسية، ولها اختبار لمسارها الأساسي.

## نتائج قياس الأداء (الهدف الأولي: 1,000 كيان و3,000 علاقة)

البيئة: حاوية Linux بـ 4 أنوية، وNode 22، وPGlite في الذاكرة، وChromium 141 دون واجهة ودون GPU (رسم برمجي). أرقام المتصفح هنا متشائمة مقارنة بجهاز عادي فيه GPU، والقياس الواحد متذبذب، فهي أرقام استرشادية.

**النواة وقاعدة البيانات** (`npm run bench`):

| العملية | الزمن |
|---|---|
| تطبيق 4,998 عملية دفعة واحدة (المخفّض) | 17 ms |
| عكسها (تجهيز التراجع) | 10 ms |
| تحريك بطاقة واحدة (تطبيق وعكس) | < 9 ms |
| الجوار حتى عمق 3، وأقصر مسار، وتحليل الأثر | 1 إلى 3 ms |
| لوحات المعلومات الأربع | 2 إلى 11 ms لكل لوحة |
| البحث | 4 إلى 5 ms |
| قاعدة البيانات: إدخال 4,998 سجلاً في معاملة واحدة | 1.3 s |
| قاعدة البيانات: تحميل اللقطة كاملة (1.9 MB) | 135 ms |
| قاعدة البيانات: تحريك بطاقة واحدة | 6 ms |

**اللوحة في المتصفح**:

| السيناريو | النتيجة |
|---|---|
| فتح لوحة فيها 1,000 بطاقة | نحو 1.2 إلى 1.5 s |
| كل البطاقات (1,000) وكل الخطوط (2,997) ظاهرة معاً أثناء التحريك | زمن الإطار: الوسيط 16.8 ms، وp90 150 ms |
| السحب عند تكبير عادي (يُرسم نحو 10 بطاقات من الألف) | الوسيط 16.7 ms، وp90 50 إلى 150 ms. والخريطة المصغرة تضيف تكلفة ملحوظة مع الأعداد الكبيرة |

تحسينات طُبّقت أثناء القياس:
- المخفّض بالنسخ عند الكتابة: من 1.6 s إلى 17 ms.
- إدخال جماعي في الخادم: من 4.7 s إلى 1.3 s.
- إعادة استعمال كائنات الخطوط وإخفاء أسمائها عند الابتعاد: الوسيط من 50 ms إلى 16.8 ms.
- تأجيل النسخة المحلية إلى وقت خمول المتصفح.

الخطوة التالية للأداء:
- تبسيط الخريطة المصغرة، أو إخفاؤها تلقائياً فوق عدد معيّن.
- تجميع العناصر البعيدة (clustering) عند الابتعاد الشديد.
- تحميل كسول لكل لوحة عند تجاوز عشرات الآلاف.

## حدود معروفة

1. **يحتاج خادم Node**: بخلاف تطبيقات المستودع الأخرى، لا يعمل على GitHub Pages. يُشغَّل محلياً (`npm run dev` أو `npm start`) أو يُنشر على خدمة تدعم Node مع PostgreSQL.
2. **مستخدم واحد وتبويب واحد**: لا تزامن لحظي بين تبويبين مفتوحين. وكل تبويب يرسل عملياته، والأحدث يغلب على مستوى الحقل.
3. **لا مصادقة بعد**: لا تعرض الخادم على الإنترنت.
4. **سجل التراجع خاص بالجلسة** (في الذاكرة). أما سجل التعديلات الدائم ففي `change_events`.
5. **النسخ واللصق داخل التطبيق** فقط، لا عبر حافظة النظام.
6. **الواجهة مصمّمة للحاسوب أولاً**: اللمس يعمل في اللوحة، لكن الشريط الجانبي واللوحات لم تُكيَّف للجوال بعد.

## الخطوة التالية المقترحة

1. نقل إعداد لوحات المعلومات إلى قاعدة البيانات، ثم بناء **منشئ لوحات المعلومات** (المرحلة 3 و4).
2. **منظور الهيكل** (يدعم تعدد الآباء) و**Kanban** و**الخط الزمني** و**حفظ المناظير**.
3. **الترتيب التلقائي (ELK.js في Web Worker)** مع حفظ الترتيب اليدوي، و**الطيّ والتوسيع**.
4. **الاستيراد**: JSON ثم CSV.
5. **المرحلة 5**: مزوّد Claude عبر واجهة `AiProvider`، بدءاً بـ «حوّل هذه الملاحظات إلى مهام» و«اقترح روابط»، مع شاشة موافقة.
